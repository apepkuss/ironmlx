# IronMLX 0.2.0 发布说明

IronMLX 0.2.0 在本地 Apple Silicon 文本与视觉生成能力之上，新增本地模型导入、语音合成、类型化决策模型服务、更多客户端集成以及模块化运行时架构。`v0.2.0-rc.1` 等候选版 tag 是用于验证和反馈的预发布版，不会通过稳定版更新通道发布。

## 系统要求

- Apple Silicon（arm64），macOS 26.4 及以上；不支持 Intel Mac。
- 内存需求取决于模型大小、量化、上下文和并发量；架构受支持不代表任意设备都能加载该 checkpoint。
- 模型权重和辅助资源需单独下载，并继续受上游许可条款约束。

## 导入这台 Mac 上已有的模型

- Dashboard 的**模型 → 模型管理**可导入包含 `config.json`、权重和 tokenizer 的现有模型目录。
- IronMLX 会复制并校验模型，将其纳入托管模型库；原始目录保持不变。
- 含有效 IronMLX manifest 的快照会保留仓库身份；其他本地目录存放在托管的 `standalone` 命名空间下。
- 导入前的确认步骤会显示来源、目标位置和复制大小；完整复制需要足够的可用存储空间。

目录选择与模型管理说明见[用户指南](../user-guide.md#导入已有模型)。

## 语音合成与语音档案

- App 支持已验证的 `mlx-community/IndexTTS-2.5-fp16` 配置，包括资源准备、模型加载、完整 WAV 响应和流式 PCM 输出。
- `POST /v1/audio/speech` 接受 Base64 参考音频或托管 voice ID。
- 语音管理端点和 Dashboard 控件可创建、更新、预听、启用和删除本地语音档案。
- 托管的参考录音保留在本机，IronMLX 不会上传。

支持的格式与限制见[语音 API](../audio-speech-api.md) 和 [TTS 模型下载指南](../tts-model-download.md)。

## 决策模型服务

- App 可下载、加载、卸载并恢复类型化决策模型 `aac6fef/laya-multilingual-mlx`。
- `POST /v1/systemone` 提供第一阶段、兼容 TypeSafe 的 System One 契约。
- Dashboard 状态包含决策运行时请求计数，以及近期延迟、token 速率和问题速率指标。
- 独立 CLI 提供相同的类型化执行路径，用于开发与验证。

请求契约、运行时设置与客户端示例见 [Laya 与 System One 指南](../laya-systemone-api.md)。

## API 与客户端兼容性

- 现有 OpenAI Chat Completions、Responses 和 Anthropic Messages 路由继续用于兼容的文本与视觉模型。
- 能够可靠判定时，模型发现会返回有效上下文和输出 token 容量。
- 受支持的原生模板会为最终答案保留输出空间，并在重放时保留 reasoning item 的 completed/incomplete 状态。
- DeepSeek Harness CLI 和 Desktop 配置指南加入现有 Hermes Agent 与 oh-my-pi 集成。

## 运行时与发布工程

- 共享模型、缓存和采样代码拆分至 `ironmlx-core` 和 `ironmlx-lm`；调度与执行位于 `ironmlx-runtime`；语音和决策路径分别使用 `ironmlx-audio` 与 `ironmlx-decision`。
- CI 变更范围解析、分发材料、签名更新源和发布工作流增加了可复现性与失败边界检查。
- RC 序号与 App build number 相互独立；`CFBundleVersion` 全局递增，以便 Sparkle 跨发布线比较更新。

## 兼容性与已知限制

- 语音合成仅限文档中的 IndexTTS 2.5 配置和输出格式；仅识别模型元数据不代表运行时受支持。
- 决策服务仅限文档中的 Laya 模型和 System One 契约。
- DeepSeek Harness 兼容性以[集成指南](../dsh.md)中记录的版本和请求路径为准。
- DiffusionGemma、MTP、DFlash2 和多模态支持继续受各自的模型限制约束。部署前请查看[支持的模型](../supported-models.md)与[已知问题](../known-issues.md)。
- RC 与稳定版使用独立更新通道，安装或切换通道是显式用户操作。
