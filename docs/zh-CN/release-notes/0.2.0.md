# IronMLX 0.2.0 发布说明

IronMLX 0.2.0 在本地 Apple Silicon 文本与视觉生成能力之上，新增本地模型导入、语音合成、文本、图片与音频向量、类型化决策模型服务、更多客户端集成以及模块化运行时架构。`v0.2.0-rc.1` 等候选版 tag 是用于验证和反馈的预发布版，不会通过稳定版更新通道发布。

## RC2 相对 RC1 的变化

RC2 候选版使用 tag `v0.2.0-rc.2`，产品版本保持 `0.2.0`，App build 从 RC1 的 `5` 升至 `6`。本节记录候选版的源码变化；签名、公证及安装／升级验收结果另行绑定最终发布产物记录。

- **Qwen Image 2.1：**通过 `POST /v1/images/generations` 和 `POST /v1/images/edits`，为 `mlx-community/Qwen-Image-2.1-MLX-4bit` 提供文生图及单图条件编辑，并支持 App 下载和模型生命周期管理。当前不支持蒙版局部重绘和图片变体。使用方式见[图片生成 API](../image-generation-api.md)，并需遵守模型的 Qwen Research License 条件。
- **支持模型目录：**按类型及量化变体组织可下载模型，显示仓库、大小、内存及验证状态提示。Dashboard 提供下载暂停／恢复和更新控制。辅助草稿模型与普通模型分别标识；可下载不代表运行时兼容。见[用户指南](../user-guide.md#下载与更新模型)。
- **EmbeddingGemma 2：**新增 BF16 与 affine4 文本、图片及音频向量、有序多模态输入和 Dashboard 指标。当前不支持视频向量。见 [Embedding API](../text-embeddings.md)。
- **Qwen3.8 DFlash2：**新增验证及调度改进、跨请求 ragged 草稿合批、适用于已验证配置的 M5 profile，以及前缀缓存未命中时的 prefill 优化。KV 容量和输出尾部修复避免受影响请求提前终止；Chat Completions 流未完整结束时返回错误，不再报告成功。Tree 验证和 position-keyed sampling 是显式选项，更宽的验证窗口受 checkpoint 和运行时能力检查约束。
- **Qwen3.6 35B A3B DFlash2：**新增对应的 MoE 主模型／草稿执行路径、自适应草稿预算，以及对符合条件的 greedy、无约束请求逐行保持一致的 ragged 合批。支持 affine 4/5/6/8-bit 主模型及以 4-bit 或 BF16 加载的匹配草稿；拒绝 OptiQ 主模型和 8-bit 草稿。采样或受约束请求保留各自的执行路径。实验性 M5 affine4 投影可能改变相对普通 MLX 解码的输出。
- **DFlash2 下载兼容性：**允许以“仅下载”方式获取主模型采集层数量与草稿自身层数不同的辅助草稿，同时保留其辅助模型标识；加载和主模型／草稿配对继续执行兼容性检查。见[支持的模型](../supported-models.md)及 [DFlash2 配置与使用](../dflash2-server-api.md)。加速仍仅支持文本，不能与 MTP 同时使用；性能取决于 checkpoint、硬件和负载。
- **文档与构建可复现性：**重组中英文指南和网站，统一 Embedding API 命名，并获取干净 CI 构建所需的固定 MLX 验证提交。

## 系统要求

- Apple Silicon（arm64），macOS 26.4 及以上；不支持 Intel Mac。
- 内存需求取决于模型大小、量化、上下文和并发量；架构受支持不代表任意设备都能加载该 checkpoint。
- 模型权重和辅助资源需单独下载，并继续受上游许可条款约束。

## 导入这台 Mac 上已有的模型

- Dashboard 的**模型 → 模型管理**可导入包含 `config.json`、权重和 tokenizer 的现有模型目录。
- IronMLX 会复制并校验模型，将其纳入托管模型库；原始目录保持不变。
- 含有效 IronMLX manifest 的快照会保留仓库身份；其他本地目录存放在托管的 `standalone` 命名空间下。
- 导入前的确认步骤会显示来源、目标位置和复制大小；完整复制需要足够的可用存储空间。

目录选择与模型管理说明见[用户指南](../user-guide.md#导入已有模型)。

## 语音合成与语音档案

- App 支持已验证的 `mlx-community/IndexTTS-2.5-fp16` 配置，包括资源准备、模型加载、完整 WAV 响应和流式 PCM 输出。
- `POST /v1/audio/speech` 接受 Base64 参考音频或托管 voice ID。
- 语音管理端点和 Dashboard 控件可创建、更新、预听、启用和删除本地语音档案。
- 托管的参考录音保留在本机，IronMLX 不会上传。

支持的格式与限制见[语音 API](../audio-speech-api.md)；App 声音配置和模型设置见[用户指南](../user-guide.md#语音合成)。

## 文本、图片与音频向量

- EmbeddingGemma 2 BF16 与 affine4 版本支持 `POST /v1/embeddings`，可输入文本、图片、音频及有序组合，也支持多段媒体。
- 模型适配器完成 RGB 转换、缩放、图片 patch 准备和图片 token 放置；客户端提交原始 JPEG/PNG/WebP data URL。音频适配器解码 WAV/FLAC/MP3，混合声道并重采样至 16 kHz，再准备模型专用 log-mel 特征和音频 token。
- 输出支持 128、256、512 和 768 维，可使用浮点或 base64 编码。
- Dashboard 状态显示向量队列活动、完成／失败请求数、P50 延迟、输入 token 吞吐和向量吞吐。
- 向量模型复用加载、卸载、固定、TTL 与内存保护；当前不支持视频向量。

精确输入限制及 BF16／affine4 验证范围见[Embedding API](../text-embeddings.md)。

## 决策模型服务

- App 可下载、加载、卸载并恢复类型化决策模型 `aac6fef/laya-multilingual-mlx`。
- `POST /v1/systemone` 提供第一阶段、兼容 TypeSafe 的 System One 契约。
- Dashboard 状态包含决策运行时请求计数，以及近期延迟、token 速率和问题速率指标。
- 独立 CLI 提供相同的类型化执行路径，用于开发与验证。

请求契约、运行时设置与客户端示例见 [Laya 与 System One 指南](../laya-systemone-api.md)。

## API 与客户端兼容性

- 现有 OpenAI Chat Completions、Responses 和 Anthropic Messages 路由继续用于兼容的文本与视觉模型。
- 能够可靠判定时，模型发现会返回有效上下文和输出 token 容量。
- 受支持的原生模板会为最终答案保留输出空间，并在重放时保留 reasoning item 的 completed/incomplete 状态。
- DeepSeek Harness CLI 和 Desktop 配置指南加入现有 Hermes Agent 与 oh-my-pi 集成。

## 运行时与发布工程

- 共享 tensor、权重、缓存和采样代码拆分至 `ironmlx-core` 和 `ironmlx-lm`；图片生成位于 `ironmlx-image`；调度与执行位于 `ironmlx-runtime`；语音和决策路径分别使用 `ironmlx-audio` 与 `ironmlx-decision`。
- CI 变更范围解析、分发材料、签名更新源和发布工作流增加了可复现性与失败边界检查。
- RC 序号与 App build number 相互独立；`CFBundleVersion` 全局递增，以便 Sparkle 跨发布线比较更新。

## 兼容性与已知限制

- 语音合成仅限文档中的 IndexTTS 2.5 配置和输出格式；仅识别模型元数据不代表运行时受支持。
- 决策服务仅限文档中的 Laya 模型和 System One 契约。
- DeepSeek Harness 兼容性以[集成指南](../dsh.md)中记录的版本和请求路径为准。
- DiffusionGemma、MTP、DFlash2 和多模态支持继续受各自的模型限制约束。部署前请查看[支持的模型](../supported-models.md)与[已知问题](../known-issues.md)。
- RC 与稳定版使用独立更新通道，安装或切换通道是显式用户操作。
