# IronMLX 0.3.0

[English](../../release-notes/0.3.0.md)

## 相对 0.2.0 的变化

本发布线新增原生语音识别、实时音频 API、OpenCode 集成与可选 M1 GPU 执行计划，
并改进模型组件下载、聊天参数兼容、内存恢复和 DFlash2 启动。
发布状态与下载入口以 [GitHub Releases](https://github.com/apepkuss/ironmlx/releases) 为准。

- 新增本地 Qwen3-ASR 0.6B/1.7B 转写、长音频自动分段、流式结果与每模型音频限制。
- 新增 Qwen3 ForcedAligner 时间戳与 SRT/VTT 字幕，以及 Nemotron 3 说话人分离和可选实时说话人标注。

- Chat Completions 支持 `max_completion_tokens`、`frequency_penalty` 和 `presence_penalty`；请求省略输出限制时使用所选模型的默认预算。

## 语音识别与实时音频

Qwen3-ASR 通过原生 Rust/MLX 引擎运行，支持 App 管理后端和 CLI 模型池。
文件转写支持 JSON、纯文本与 SSE，长录音自动分段。每个 ASR 模型独立保存时长与输出 Token 限制。

Qwen3 ForcedAligner 提供独立对齐、带时间戳转写与 SRT/VTT 字幕。
Nemotron 3 提供独立说话人分离、带说话人标签的转写，以及实时会话中的可选连续说话人标注。
WebSocket 与 WebRTC 共用有界会话准入、可选 CPU 服务端 VAD，以及取消和清理行为。
WebRTC 通过音频轨道传输媒体，通过 DataChannel 交换会话配置和转写事件。

Dashboard 管理模型、参数和服务状态，录音与结果展示由上游客户端负责。
语音识别不会翻译录音或合成语音；降噪不在本次发布范围内。说话人标签只在当前会话中有效，不识别个人身份。
支持的检查点、格式、资源限制和协议扩展见[语音识别、对齐与说话人分离 API](../audio-transcriptions-api.md)。

## 下载与修复

下载可独立选择和校验权重组件，无需同时下载无关的主权重。
修复流程处理缺失或无效的模型组件，完成后的快照能否在本版本运行仍由原生预检决定。
使用方法见[模型管理](../user-guide.md)。

## OpenCode 集成

Dashboard 可通过 OpenCode 原生 OpenAI-compatible Chat Completions provider
配置 OpenCode CLI 与 Desktop 2.2.5 或更高版本。一键配置保留无关设置，读取实际模型容量，
并支持仅安装 Desktop 及独占 DFlash2 服务的场景。

默认关闭思考。兼容的 Qwen3.8 模板提供 Low、Medium、Xhigh 变体；流式思考使用
`reasoning_content`，并在后续轮次回放。后端同时接受 OpenCode 默认工具 schema
使用的起始锚定前缀模式。已有验证包括 CLI 文本与 read 工具闭环、Desktop 模型选择及原生思考。
Desktop 工具执行、TUI、视觉和长上下文自动压缩不在已记录覆盖范围内。
详见 [OpenCode 配置与验证](../opencode.md)。

## DFlash2 启动与模型设置

App 会在 DFlash2 加载和 warmup target／draft 期间等待后端 HTTP 就绪，
进程提前退出仍会立即报错。启动和重启保持配置的目标模型与每模型 draft 设置一致。
这些修改不取消模型加载和请求准入的内存限制。详见 [DFlash2 配置](../dflash2-server-api.md)。

## 可选 M1 GPU 计划

`ironmlx serve` 和 `ironmlx generate` 支持 `--m1-profile auto|off`，默认 `auto`，
标准 App 启动也采用此默认值；显式 `off` 可关闭专用通道。
`auto` 仅在真实 M1 Pro／Max 上为 Qwen3.8-27B affine4/group64 选择该计划。
普通、MTP 和 DFlash2 target forward 共用逐模型计划，不兼容设备与模型沿用既有路径。
该计划不增加常驻权重副本，也不改变内存上限、投机预算或 M5 默认设置。

只有真实 M1 Pro／Max 硬件返回 M1 计划信息，即使专用通道关闭或模型不受支持也可报告状态；
其他硬件的接口响应省略 M1 专用字段。

已有 M1 Pro 真实模型回归覆盖普通、MTP 和 DFlash2 共 254 个场景，draft 权重使用 4bit。
本记录不声称已有 M1 Max 实机结果或受控提速结论；该计划尚未实现 ANE、专用 tiled
prefill GEMM 和专用 attention 内核。
详见 [M1 GPU 推理](../m1-gpu-inference.md) 与[验证记录](0.3.0-validation.md)。

## 聊天参数与内存恢复

Chat 输出预算依次采用 `max_completion_tokens`、`max_tokens`、所选模型的默认配置、256。
显式预算须为正数，输入加输出仍须满足配置的上下文限制。
请求级频次和出现惩罚允许 [-2, 2]，DiffusionGemma 拒绝非零惩罚。
详见[文本与视觉 API](../text-vision-api.md) 和[参数验证记录](../../validation/chat-completions-parameters.md)。

待完成的模型加载预留继续限制准入，但不与逐步分配的权重重复叠加来判断压力。
已分配权重不再需要重复的首次使用预留。
缓存回收与空闲模型驱逐会重新采样内存，再决定是否继续驱逐；原有压力迟滞和遥测降级保护继续生效。
详见[内存管理](../engine-pool.md)。
