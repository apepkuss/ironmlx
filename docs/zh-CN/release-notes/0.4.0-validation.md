## 发布正文与用户可见行为

正式版摘要现按 **New features**、**Fixes** 分组，简体中文对应 **新增功能**、**问题修复**。
现有渲染器会将两组放入 GitHub Releases 正文；下载链接、发布状态和兼容说明仍由共享
模板生成。其他版本和模板均不修改。`RELEASE-NOTES.md` 及 HTML 仅为本地预览，不编辑
或发布 GitHub Release 正文。

内置对话的目标输出预算为配置／默认预算与已知上下文一半的较小值。4096-token 上下文
最多请求 2048-token 输出，即使配置了 4096。思考和可见答案共用该额度。最新输入本身
超过上下文一半时，剩余估算可进一步降低输出；必要时仍裁剪旧问答。后端／API token
上限和保存的模型设置不变。tokenizer／模板估算有偏差时，仍可按后端返回的正数且更小
的剩余输出额度重试一次。

控制器新的长消息夹具通过 fake transport 覆盖半上下文上限下的重试，token 数是合成的，
不属于真实 tokenizer 或模型证据。实测需单独记录输入、响应和历史范围，包括是否通过
首次 413 响应才发现服务端上下文限制。

主动停止保留非空部分回复。本轮未手动将输出降低至 512。维护者仅协助从系统菜单栏
打开 Chat，其余控件由 CUA 操作；本轮未重做 Chat 窗口的关闭重开。

直接 admission 探测使用 4213 UTF-8 字节，构造器估算输入为 2106 token，真实 tokenizer
报告 2117。已知 4096 上下文时，初始 Chat 输出预算应为 1990；实际观察到的 HTTP 413
只允许 1979 输出 token。原生 Chat 随后对逐字节相同的输入完成了 `LONG_OK` 回复。
预算恢复由匹配的探测、源码规则和原生成功结果推断；没有直接抓取原生初始请求或重试
次数。有界重试另由本轮 HTTP／SSE 单测覆盖。已加载模型元数据给出架构上下文 262144，
而 `/v1/models` 给出实际 4096；不将首次 413 学习上下文记作已抓取的原生事件。

本轮包含 17 个脚本推理请求、6 个原生用户提示和 1 个不生成内容的 413 admission 探测。
内部 Chat 预热／重试不计入上述用户提示数。未执行性能基准或额外权重下载。
