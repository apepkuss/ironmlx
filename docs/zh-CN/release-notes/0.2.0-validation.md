## 复现与证据

复用验收命令需要 macOS、当前没有运行中的 IronMLX、已有的托管模型快照，以及尚不存在
的输出目录：

```bash
python3 scripts/validate-app-installation.py \
  --candidate dist/IronMLX.app \
  --baseline v0.1.0=/absolute/path/to/published-v0.1.0/IronMLX.app \
  --baseline v0.2.0-rc.4=/absolute/path/to/published-rc4/IronMLX.app \
  --model /absolute/path/to/existing/managed/model/snapshot \
  --output .build/release-readiness/stable/installation
```

`installation/results.json` 记录各路径的 Bundle 元数据、health、进程身份、推理响应和
清理结果；相邻的 before／after 清单记录每个受检文件的哈希，后端与 App 日志保留真实
恢复顺序。`installation/candidate-manifest.json`、归档中的 `SHA256SUMS`、
`published/downloads.json` 及 `build.log` 将结果绑定到本次输入和本地候选包。

## 完整 App 的 Sparkle 验收入口

`scripts/validate-full-app-update.py` 进一步使用完整 App 检查实际 Sparkle 安装、归档
篡改及下载中断。它要求 Developer ID 候选包、已发布基线及内嵌 Sparkle helpers 来自
同一签名团队，并提供匹配的本地签名身份。外层 App 的 ad-hoc 签名与 Developer ID
Sparkle helper 混用不构成有效验收环境：Sparkle 会在安装前拒绝 updater 连接。

工具生成仅供测试的副本，配置独立 Bundle ID、Foundation home、本机 HTTPS 更新源
及临时更新密钥。它核对可执行代码和其他载荷与输入一致，仅允许 Bundle 元数据及签名
变化。独立 Bundle ID 也隔离 CFPreferences；单独设置 `CFFIXED_USER_HOME` 不能完整
隔离该存储。正常安装必须替换 App、重新启动、恢复固定的真实模型并推理；失败路径
必须保留旧 App、数据及推理能力。调用方可提供一套已信任的 TLS 证书／私钥供多轮复用，
并负责在会话结束后移除信任。未提供可选 TLS 参数时，macOS 可能要求用户授权临时信任
创建和清理。

以下命令供维护者使用，不会发布更新：

```bash
python3 scripts/validate-full-app-update.py \
  --candidate /absolute/path/to/signed/IronMLX.app \
  --baseline v0.1.0=/absolute/path/to/published-v0.1.0/IronMLX.app \
  --baseline v0.2.0-rc.4=/absolute/path/to/published-rc4/IronMLX.app \
  --model /absolute/path/to/existing/managed/model/snapshot \
  --signing-identity 'Developer ID Application: Name (TEAMID)' \
  --output .build/release-readiness/stable-preparation/full-app-updates-signed
```

后续准备结果记录于本地
`.build/release-readiness/stable-preparation/readiness.json` 证据索引，包含精确源码及 CI
身份、签名产物哈希、公证回执和最终完整 App 升级结果。本份初始 build `9` 记录不会在
缺少对应证据时宣称后续门禁通过。

## 剩余正式发布门禁

上述配置的 build number、本地手动安装、恢复和数据保留缺口已补齐。版本一致性、分发
授权、确定性 SBOM、静态 Bundle 及模型分发边界检查通过。发布身份行为测试 15 项、发布
失败边界测试 10 项、真实 Sparkle 签名及更新策略测试 5 项、Release 正文生成测试 11 项、
Swift Release 测试 508 项通过；这些测试不会公开发布，也不代表生产升级通过验收。

本次准备仍需提交最终源码，并使该精确提交通过 CI。创建不可变 `v0.2.0` tag、验收
stable 通道 Bundle 身份、Developer ID 签名、App／DMG 公证、Gatekeeper 和最终正式
产物，仍属于后续发布步骤。本地候选包禁用了更新，不能直接改名或上传为正式版。
本轮手动升级也未验证从稳定版基线通过生产 Sparkle 完成安装。没有移动分支、创建 tag、
公开 Release 或发布更新源。
