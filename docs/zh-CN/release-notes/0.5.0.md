# IronMLX 0.5.0

[English](../../release-notes/0.5.0.md)

## 自 0.4.0 以来的变更

本版改进前缀缓存复用和内存管理，并修复图片预填充与 Gemma4 注意力行为。
本文描述准备中的版本；发布状态和下载见
[GitHub Releases](https://github.com/apepkuss/ironmlx/releases)。

<!-- release-summary:stable -->
#### 新增功能

- 新增 DFlash2 磁盘前缀缓存，服务重启后可复用符合条件的前缀。
- 支持不配置 SSD 目录的纯内存前缀缓存，并回收缓存前缀，为推理请求腾出空间。
- 默认让符合条件的模型权重保持 GPU 驻留，提供自动容量限制和显式 CLI 控制。

#### 问题修复

- 限制 DFlash2 前缀缓存内存，在内存压力或请求需要更多空间时缩减缓存。
- 修复首个长图片请求在分块预填充中挂起的问题。
- 修复 Gemma4 使用 paged KV 缓存时滑动窗口越界的问题，并在每个图片块内部应用双向注意力。
- 将 quinn-udp 更新至 0.5.16，修复 RUSTSEC-2026-0538。

## 前缀缓存

CLI 参数 `--prefix-lru-cache-max-bytes` 可启用纯内存前缀复用。未配置该预算时，
内存 LRU 缓存仍然关闭。添加 `--paged-prefix-cache-dir` 后，还可将符合条件的前缀保存到
磁盘。普通与 MTP 服务为此缓存使用 paged K/V；DFlash2 保持 dense K/V 和现有 decode
kernel。

DFlash2 配置磁盘目录时，必须显式设置内存缓存预算。
`--ssd-prefix-cache-max-gb` 限制该目录内的 DFlash2 存储容量。仅恢复兼容条目；无效或
不兼容条目不会被算作缓存命中。前缀在可复用的对话轮次边界保存。缓存可在内存压力下
及请求准入前释放条目；被回收的前缀在后续请求中可能需要重新预填充。

这些改动不增加 DFlash2 对 MTP、Prompt Lookup、KV 量化或 Active KV offload 的支持。
CLI 缓存控制不代表新增了 Dashboard 控件。详见
[DFlash2 配置](../dflash2-server-api.md)。

## GPU 权重驻留

CLI 默认使用 `--resident-weights auto`。符合条件的加载会在总驻留分配不超过设备推荐
工作集的三分之二时，让权重缓冲区保持 GPU 驻留。`on` 不受此容量条件限制地请求驻留；
`off` 关闭驻留。App 也为后端启用自动驻留。

驻留分配不能被压缩或换出，因此会减少其他工作可用的内存。是否符合自动驻留条件取决于
模型和设备。DFlash2 使用 wired-memory 路径，而非逐缓冲区驻留。本版不宣称普遍的
吞吐提升，也不增加对超出可用内存模型的支持。

## 图片预填充与 Gemma4 注意力

长图片输入的首次分块预填充请求可继续完成，修复了此前的调度挂起。Gemma4 的 paged KV
注意力现在遵守滑动窗口限制；同一图片块内的 token 可双向注意。这些修复不扩展支持的
模型目录。
