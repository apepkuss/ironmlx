# cxx-mlx P6.5: Safe API 风格 Rust 化改造 设计文档

**日期：** 2026-05-06
**作者：** Claude（与 Boss 协作）
**目标阶段：** P6.5 — `mlx` crate 公开表面的 Rust 风格重构

---

## 1. 目标与范围

P0–P6 已建成完整的 3 层 FFI（C++ shim → cxx::bridge → safe API），功能覆盖 MLX 主要子系统。但 safe API 表面在多处仍带有 C++ 重载残留与 MLX 上游缩写，不符合 Rust 惯例。P6.5 一次性把公开表面改成 Rust 风格的高质量库 API。

**改动范围：仅 `mlx` crate**。`mlx-sys` shim 和 cxx::bridge 完全不动。

### 1.1 已批准的 7 项决策

| # | 主题 | 决策 |
|---|---|---|
| Q1 | 算子重载 | 实现 `std::ops::{Add,Sub,Mul,Div,Neg}` for `&Array` / `Array`，panic on err；保留 `Array::add()` 等方法返回 `Result` |
| Q2 | random 17 个分布 | 统一改 builder + `.sample()` 链式；废弃所有 `*_default` / `*_n` / `*_shaped` 后缀 |
| Q3 | MLX 缩写命名 | `_mm` → `_matmul`（4 个）；保留 `addmm` / `qqmm`（BLAS / MLX 领域名词） |
| Q4 | Shape 抽象 | 引入 `Shape` newtype + `IntoShape` trait |
| Q5 | re-export 策略 | root 仅核心类型（`Array` / `Dtype` / `Element` / `Error` / `Result` / `Shape` / `IntoShape`），其余走子模块路径 |
| Q6 | 构造函数 | 删除 `Array::from_slice`，改 `impl<T, S> TryFrom<(&[T], S)> for Array` |
| Q7 | 派生 trait | enum 加 `#[non_exhaustive]`；`Array` 加 `Clone` / `Display`；`Dtype` / `CompileMode` 加 `Default` / `Display`；`Array` 不实现 `PartialEq`（保留显式 `array_equal()`） |

### 1.2 不在范围内

- `mlx-sys` 任何修改
- 新功能添加（仅 API 风格重构）
- 性能优化
- 错误信息国际化
- 给 `Array` 实现 `PartialEq`（决策为不实现）
- 给 `*_n` / `*_shaped` / `*_default` 保留兼容 alias（按 CLAUDE.md "不能写兼容性代码"原则）

3 层 FFI 不变。本阶段所有改动局限在 `mlx/src/` 下：

## 3. 详细设计

### 3.1 `mlx/src/shape.rs`（新建）

```rust
use smallvec::SmallVec;

/// 数组形状。Rank 通常 ≤ 8（SmallVec inline）；更大形状自动堆分配。
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct Shape(SmallVec<[i32; 8]>);

impl Shape {
    pub fn new() -> Self;                    // empty (scalar)
    pub fn rank(&self) -> usize;
    pub fn numel(&self) -> usize;            // ∏dims；空形状 → 1（标量）
    pub fn is_scalar(&self) -> bool;         // rank() == 0
    pub fn as_slice(&self) -> &[i32];
}

impl std::ops::Deref for Shape {
    type Target = [i32];
    fn deref(&self) -> &[i32] { self.0.as_slice() }
}

impl std::fmt::Display for Shape {
    // "[]" / "[5]" / "[2, 3, 4]"
}

impl IntoIterator for Shape { type Item = i32; ... }
impl<'a> IntoIterator for &'a Shape { type Item = &'a i32; ... }

impl From<Vec<i32>>     for Shape;
impl From<&[i32]>       for Shape;
impl<const N: usize> From<[i32; N]> for Shape;
impl<const N: usize> From<&[i32; N]> for Shape;
impl From<()>           for Shape;             // scalar
impl From<i32>          for Shape;             // rank-1, single dim
impl From<(i32,)>       for Shape;
impl From<(i32, i32)>   for Shape;
impl From<(i32, i32, i32)> for Shape;
impl From<(i32, i32, i32, i32)> for Shape;
// 5+ 元 tuple 不便利化（罕见，用 Vec/数组）

/// 任何能转成 `Shape` 的类型。所有形状参数走这个 trait。
pub trait IntoShape {
    fn into_shape(self) -> Shape;
}

// blanket：凡是 From<T> for Shape，自动 impl IntoShape for T
impl<T: Into<Shape>> IntoShape for T {
    fn into_shape(self) -> Shape { self.into() }
}
```

### 3.2 `mlx/src/array.rs`

#### 3.2.1 `TryFrom` 替代 `from_slice`

```rust
impl<T: Element, S: IntoShape> TryFrom<(&[T], S)> for Array {
    type Error = Error;
    fn try_from((slice, shape): (&[T], S)) -> Result<Array> { ... }
}
```

调用示例：
```rust
let a = Array::try_from((&[1.0_f32, 2.0, 3.0, 4.0][..], (2, 2)))?;
let b = Array::try_from((&data[..], &[batch, seq, dim]))?;
```

#### 3.2.2 `shape()` 返回 `Shape`

```rust
impl Array {
    pub fn shape(&self) -> Shape { ... }
}
```

#### 3.2.3 形状参数全部 `impl IntoShape`

```rust
impl Array {
    pub fn zeros<S: IntoShape>(shape: S, dtype: Dtype) -> Result<Array>;
    pub fn reshape<S: IntoShape>(&self, shape: S) -> Result<Array>;
    pub fn broadcast_to<S: IntoShape>(&self, shape: S) -> Result<Array>;
    pub fn slice<S: IntoShape>(&self, start: S, stop: S) -> Result<Array>;
    pub fn slice_strided<S: IntoShape>(&self, start: S, stop: S, strides: S) -> Result<Array>;
    pub fn transpose_axes<S: IntoShape>(&self, axes: S) -> Result<Array>;
    // 其他取形状参数的方法同理
}
```

> 设计取舍：`transpose_axes` 接受的是 axis 列表而非 shape，但形态相同（`&[i32]` / `(i32, i32)`）。复用 `IntoShape` 减少类型增生；语义在方法名里区分。

#### 3.2.4 `Clone` / `Display`

```rust
impl Clone for Array {
    // 调 mlx_sys 的 array_clone（MLX refcount，零数据拷贝）
    fn clone(&self) -> Array { ... }
}

impl std::fmt::Display for Array {
    // 短表示。调用 MLX `print` 不可行（写 stdout）；改为 "Array<f32>([2, 3])" 形式
    // 完整数据展示由用户显式 `array.to_vec()` + 自行格式化
}
```

#### 3.2.5 算子重载

```rust
// 二元算子：&Array op &Array
impl<'a, 'b> std::ops::Add<&'b Array> for &'a Array {
    type Output = Array;
    fn add(self, rhs: &'b Array) -> Array {
        Array::add(self, rhs).expect("Array + Array failed")
        // expect 消息包含 MLX 原错误（通过 Error::Display）
    }
}

// 同样实现：Sub / Mul / Div for &Array
// Neg for &Array
```

owned 形式 `Array op &Array`、`Array op Array` 通过 `where` 委托给 `&Array op &Array`：

```rust
impl std::ops::Add<&Array> for Array {
    type Output = Array;
    fn add(self, rhs: &Array) -> Array { (&self).add(rhs) }
}
impl<'a> std::ops::Add<Array> for &'a Array {
    type Output = Array;
    fn add(self, rhs: Array) -> Array { self.add(&rhs) }
}
impl std::ops::Add<Array> for Array {
    type Output = Array;
    fn add(self, rhs: Array) -> Array { (&self).add(&rhs) }
}
```

panic 消息格式：`"Array + Array failed: {error}"` —— 调用方能从 backtrace 立刻看出哪个算子哪个错误。

**保留** 所有 `Array::add` / `Array::mul` / `Array::sub` / `Array::div` 方法返回 `Result<Array>`：用户需要可恢复路径时显式调方法。

#### 3.3.1 builder 通用模式

每个 builder 是独立 struct，必填参数走 `new(...)` 构造，可选参数走 setter，终态调 `sample()`：

```rust
pub struct Uniform<'k> {
    low: f64,
    high: f64,
    shape: Shape,
    dtype: Dtype,
    key: Option<&'k Array>,
}

impl<'k> Uniform<'k> {
    /// 默认 [0, 1)，f32，标量形状（rank-0）。
    pub fn new() -> Self {
        Self { low: 0.0, high: 1.0, shape: Shape::new(), dtype: Dtype::Float32, key: None }
    }
    pub fn low(mut self, v: f64) -> Self { self.low = v; self }
    pub fn high(mut self, v: f64) -> Self { self.high = v; self }
    pub fn shape<S: IntoShape>(mut self, s: S) -> Self { self.shape = s.into_shape(); self }
    pub fn dtype(mut self, d: Dtype) -> Self { self.dtype = d; self }
    pub fn key(mut self, k: &'k Array) -> Self { self.key = Some(k); self }
    pub fn sample(self) -> Result<Array> { ... }
}

impl<'k> Default for Uniform<'k> { fn default() -> Self { Self::new() } }

// 自由函数糖
pub fn uniform<'k>() -> Uniform<'k> { Uniform::new() }
```

调用示例：
```rust
let x = mlx::random::uniform()
    .low(-1.0).high(1.0)
    .shape((batch, dim))
    .dtype(Dtype::Float32)
    .key(&k)
    .sample()?;

// 默认值：
let r = mlx::random::uniform().shape((4, 4)).sample()?;  // [0,1) f32
```

#### 3.3.2 必填参数走构造

`categorical` / `bernoulli` / `multivariate_normal` 等带必填 `Array` 参数的，构造函数收：

```rust
pub fn categorical(logits: &Array) -> Categorical<'_>;

mlx::random::categorical(&logits)
    .axis(-1)
    .num_samples(10)
    .key(&k)
    .sample()?;
```

`num_samples` 与 `shape` 互斥（C++ 三个重载之一）；builder 内部用 enum 私有字段表达：

```rust
enum CategoricalShape {
    Default,                  // 默认：单样本
    NumSamples(i32),          // .num_samples(n)
    Shape(Shape),             // .shape(s)
}
```

`.num_samples(n)` 与 `.shape(s)` 后调用者覆盖前者（最后调用为准），文档明示。

#### 3.3.3 `permutation` 双模式

```rust
pub fn permutation(x: &Array) -> Permutation<'_, ArrayMode>;
pub fn permutation_range(n: i32) -> Permutation<'static, RangeMode>;
```

或更简单：两个独立 builder（`Permutation` / `PermutationRange`），导出两个 free fn。

#### 3.3.4 `state.rs` — key 管理

`key` / `seed` / `split` / `split_n` 仍是函数（无可选参数，无 builder 收益）：

```rust
pub fn key(seed: u64) -> Result<Array>;
pub fn seed(seed: u64);
pub fn split(key: &Array) -> Result<(Array, Array)>;
pub fn split_n(key: &Array, n: i32) -> Result<Array>;
```

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 测试改动量大（19 个文件） | 任务 7 集中处理；任务 1–6 各自只改自己引入的破坏点 |
| `IntoShape` blanket 与具体 `From` impl 冲突 | 用 `impl<T: Into<Shape>> IntoShape for T` 单一 blanket，不写额外 `IntoShape` 具体 impl |
| 算子 panic 信息丢失上下文 | `expect()` 消息固定格式 `"<Op> failed: {error}"`，依赖 `Error: Display` 完整输出 |
| 并发 builder 用法误解（`.shape()` 与 `.num_samples()` 互斥） | 文档示例 + 测试断言"最后调用为准" |
| 任务 5 的 17 个 builder 样板量 | 每个 builder 一个文件；可写一个内部宏 `define_random_builder!`（YAGNI 视情况引入） |
| 阶段中间不可编译 | 每任务粒度切到"独立 commit 后 `cargo build` 绿"；任务 2 和任务 3 必要时合并 |
| `Array::Display` 是否触发 eval | 实现选择：只展示 dtype + shape，不读数据；避免懒求值副作用 |

## 6. 与后续阶段的关系
