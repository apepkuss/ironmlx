# cxx-mlx P5.7: Stream/Device 全线集成 + 批量 eval + compile_clear_cache 设计文档

**日期：** 2026-05-06
**作者：** Claude（与 Boss 协作）
**目标阶段：** P5.7 — 推理基础设施架构修复

---

## 1. 目标与范围

P0–P6.5 完成后，cxx-mlx 已绑定 ~60 个算子，但 **没有任何算子允许调用方指定 `Stream`/`Device`**。MLX C++ 每个 op 末尾都接 `StreamOrDevice s = {}`，是 MLX 调度模型的核心；当前 Rust 表面只能走全局默认 stream，多 stream 并发推理（prefill/decode 分流、跨流并行）做不了。

P5.7 一次性修复三件事：

1. **`StreamOrDevice` 全线集成**（最大块）：每个算子提供"默认"和"`_on` 显式 stream"两个变体
2. **批量 `eval(arrays...)`**：一次触发多个 array 求值
3. **`mlx::compile::clear_cache()`**：绑定 MLX 的 compile cache 清理

### 1.1 已批准的设计决策

| # | 主题 | 选择 |
|---|---|---|
| Q1 | API 形态 | **B-2**：双函数 — `add(a, b)` 默认 + `add_on(a, b, target)` 显式 |
| Q2 | StreamOrDevice 类型 | **A**：公开 enum `StreamOrDevice { Default, Stream(Stream), Device(Device) }`，`_on` 函数收 `impl Into<StreamOrDevice>` |
| Q3 | `_on` 变体覆盖范围 | `ops::*` + `Array` 方法 + `fast::*` + `quantization::*` 全部覆盖；`random::*` builder 加 `.stream(s)` setter；其他模块不动 |

### 1.2 不在范围内

- `mlx::compile::compile<F>` 接受 stream（compile 闭包内 op 继承调用时的 stream context）
- `mlx::io::*`（IO 不在 device 上跑）
- `mlx::transforms::async_eval` / `synchronize` 增加 stream 参数
- `std::ops::{Add,Sub,Mul,Div,Neg}` 操作符接受 stream（语法无法承载）
- 替代旧的 thunk / lazy op 风格（B-3）

## 2. 架构

3 层 FFI 不变。改动局限在三层：

```mermaid
graph LR
    User[Rust 用户] --> SafeAPI[mlx::* safe API]
    SafeAPI --> Bridge[mlx_sys cxx::bridge]
    Bridge --> Shim[C++ shim]
    Shim --> MLX[mlx::core]
```

### 2.1 三层都要扩展

| 层 | 改动 |
|---|---|
| **C++ shim** | 每个算子的 shim 函数加 `int32_t stream_idx, uint8_t stream_device, bool has_stream, bool is_device` 四参表示 `StreamOrDevice`（cxx 不支持 `std::variant`） |
| **cxx::bridge** | 同上 4 个参数（u 类型穿过） |
| **safe API** | 加 `_on` 变体；macro 派生默认变体调 `_on` 传 `StreamOrDevice::Default` |

### 2.2 编码方案

`StreamOrDevice` 跨 FFI 编码（4 参数）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `has_target` | `bool` | `false` → monostate（默认）；`true` → 后续字段有效 |
| `is_device_only` | `bool` | `true` → device-only；`false` → 完整 stream |
| `device_type` | `u8` | `Device::DeviceType` repr |
| `stream_index` | `i32` | stream 编号（device-only 时未用） |

shim 内 helper（在 `shim_helpers.h` 加）：

```cpp
inline mlx::core::StreamOrDevice decode_stream_or_device(
    bool has_target, bool is_device_only, uint8_t device_type, int32_t stream_index) {
    if (!has_target) return std::monostate{};
    auto dev = decode_device(device_type);
    if (is_device_only) return dev;
    return mlx::core::Stream(stream_index, dev);
}
```

### 2.3 `_on` 派生 macro

为避免手写 ~100 个 `_on`：在 `mlx/src/ops/macros.rs`（新建）定义 declarative macro：

```rust
macro_rules! op_with_stream {
    (
        $vis:vis fn $name:ident ( $($arg:ident : $ty:ty),* $(,)? ) -> $ret:ty
        => $bridge:path
    ) => {
        $vis fn $name( $($arg: $ty),* ) -> $ret {
            paste::paste! { [<$name _on>]( $($arg,)* StreamOrDevice::Default ) }
        }

        $vis fn paste::paste! { [<$name _on>] }(
            $($arg: $ty,)*
            target: impl Into<StreamOrDevice>,
        ) -> $ret {
            let (has, dev_only, dev_t, idx) = target.into().encode();
            // SAFETY: target encodes valid (or default) StreamOrDevice
            let inner = unsafe { $bridge( /* args */, has, dev_only, dev_t, idx ) }
                .map_err(Error::from)?;
            Ok(Array::from_inner(inner))
        }
    };
}
```

具体宏形式实施时再敲定（可能用 `paste` crate 或 proc macro）。原则：从单一定义生成两个 fn，调用站点不写"`_on`-only"代码。

### 2.4 `Array` 方法的双变体

每个返回 `Result<Array>` 的方法都加 `_on` 变体：

```rust
impl Array {
    pub fn try_add(&self, rhs: &Array) -> Result<Array>;
    pub fn try_add_on(&self, rhs: &Array, target: impl Into<StreamOrDevice>) -> Result<Array>;

    pub fn matmul(&self, rhs: &Array) -> Result<Array>;
    pub fn matmul_on(&self, rhs: &Array, target: impl Into<StreamOrDevice>) -> Result<Array>;

    pub fn reshape<S: IntoShape>(&self, shape: S) -> Result<Array>;
    pub fn reshape_on<S: IntoShape>(
        &self, shape: S, target: impl Into<StreamOrDevice>
    ) -> Result<Array>;

    // 同理：sum/mean/max/min/argmax/exp/log/sqrt/.../slice/take/where_/...
}
```

### 2.5 random builder 加 `.stream()` setter

random 模块已是 builder 风格（P6.5 落地）。每个 builder 加：

```rust
impl<'k> Uniform<'k> {
    pub fn stream(mut self, target: impl Into<StreamOrDevice>) -> Self {
        self.target = target.into();
        self
    }
}
```

`.sample()` 内部传给 FFI。所有 11 个 builder 同样改。

### 2.6 compile 闭包内的 stream

`mlx::compile::compile<F>` 接闭包，闭包内 op 调用使用调用 `compile()` 时的全局默认 stream（MLX 行为）。**不暴露给闭包内 op 显式 stream 参数**：trace 阶段 MLX 用一个固定 stream 记录图，replay 时也用同一个。如果用户希望换 stream 调度图，应在 `compile()` 调用前用 `set_default_stream()` 切换默认（已绑定）。

### 2.7 批量 eval

MLX C++ 提供：

```cpp
void eval(std::vector<array> outputs);
```

Rust 绑定：

```rust
pub fn eval(arrays: &[&Array]) -> Result<()>;        // 同步等待
pub fn async_eval(arrays: &[&Array]) -> Result<()>;  // 异步派发
```

放在 `mlx::transforms`（与现有 `async_eval` 同模块），保留 root re-export 让 `mlx::eval(&[...])` 可用（高频）。

shim 用 `rust::Slice<const MlxArray*>` 接受 array 数组的引用。

### 2.8 compile_clear_cache

```rust
pub mod compile {
    pub fn clear_cache();
}
```

绑定 `mlx::core::compile_clear_cache()`。无参数无返回。

## 3. 详细设计

### 3.1 `StreamOrDevice` enum（`mlx/src/stream.rs` 扩展）

```rust
/// Target stream/device for an op. Mirrors MLX C++ `StreamOrDevice`.
///
/// Used by `*_on` op variants. Construct via `Stream::into()`,
/// `Device::into()`, or `StreamOrDevice::default()`.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum StreamOrDevice {
    /// Use MLX's current default stream for current thread.
    #[default]
    Default,
    /// Use this specific stream.
    Stream(Stream),
    /// Use the default stream of this device.
    Device(Device),
}

impl From<Stream> for StreamOrDevice {
    fn from(s: Stream) -> Self { StreamOrDevice::Stream(s) }
}

impl From<Device> for StreamOrDevice {
    fn from(d: Device) -> Self { StreamOrDevice::Device(d) }
}

impl From<()> for StreamOrDevice {
    fn from(_: ()) -> Self { StreamOrDevice::Default }
}

impl StreamOrDevice {
    /// Encode for FFI: (has_target, is_device_only, device_type_repr, stream_index).
    pub(crate) fn encode(self) -> (bool, bool, u8, i32) {
        match self {
            StreamOrDevice::Default => (false, false, 0, 0),
            StreamOrDevice::Device(d) => (true, true, d.device_type as u8, 0),
            StreamOrDevice::Stream(s) => (true, false, s.device.device_type as u8, s.index),
        }
    }
}
```

### 3.2 Bridge 改造（示例 `add`）

**Before**：
```rust
// mlx-sys/src/bridge/array.rs (示意)
unsafe extern "C++" {
    fn add(a: &MlxArray, b: &MlxArray) -> Result<UniquePtr<MlxArray>>;
}
```

**After**：
```rust
unsafe extern "C++" {
    fn add(
        a: &MlxArray,
        b: &MlxArray,
        has_target: bool,
        is_device_only: bool,
        device_type: u8,
        stream_index: i32,
    ) -> Result<UniquePtr<MlxArray>>;
}
```

**shim 实现**（示意）：
```cpp
std::unique_ptr<MlxArray> add(
    const MlxArray& a, const MlxArray& b,
    bool has_target, bool is_device_only, uint8_t device_type, int32_t stream_index
) {
    auto target = decode_stream_or_device(has_target, is_device_only, device_type, stream_index);
    return std::make_unique<MlxArray>(mlx::core::add(a, b, target));
}
```

### 3.3 Safe API（`mlx/src/ops/binary.rs` 示例）

```rust
use crate::stream::StreamOrDevice;

pub fn add(a: &Array, b: &Array) -> Result<Array> {
    add_on(a, b, StreamOrDevice::Default)
}

pub fn add_on(a: &Array, b: &Array, target: impl Into<StreamOrDevice>) -> Result<Array> {
    let (has, dev_only, dev_t, idx) = target.into().encode();
    // SAFETY: encode produces valid 4-param representation.
    let inner = unsafe {
        mlx_sys::array::ffi::add(a.as_inner(), b.as_inner(), has, dev_only, dev_t, idx)
    }.map_err(Error::from)?;
    Ok(Array::from_inner(inner))
}

// macro 后续替换上面两个 fn 的样板：
op_with_stream! {
    pub fn add(a: &Array, b: &Array) -> Result<Array>
        => mlx_sys::array::ffi::add
}
```

### 3.4 `Array` 方法（`mlx/src/array.rs` 示例）

类似 macro 派生，但用方法版本：

```rust
impl Array {
    pub fn try_add(&self, rhs: &Array) -> Result<Array> {
        crate::ops::binary::add(self, rhs)
    }

    pub fn try_add_on(
        &self, rhs: &Array, target: impl Into<StreamOrDevice>
    ) -> Result<Array> {
        crate::ops::binary::add_on(self, rhs, target)
    }
}
```

### 3.6 批量 eval / async_eval（`mlx/src/transforms.rs`）

```rust
/// Evaluate multiple arrays in one go. Blocks until all are computed.
pub fn eval(arrays: &[&Array]) -> Result<()>;

/// Asynchronously evaluate multiple arrays. Returns immediately;
/// arrays will become available as their computation completes.
pub fn async_eval(arrays: &[&Array]) -> Result<()>;
```

shim 接受 `rust::Slice<const MlxArray* const>`，内部展开为 `std::vector<array>` 调 MLX 的 `eval` / `async_eval`。

### 3.7 compile cache 清理（`mlx/src/compile.rs`）

```rust
/// Clear MLX's internal compile cache. Useful for long-running services
/// to release memory held by compiled graphs that won't be replayed.
pub fn clear_cache();
```

直接 binding `mlx::core::compile_clear_cache()`。

## 4. 测试策略

### 4.1 单元测试

- `StreamOrDevice` enum：`From<Stream>` / `From<Device>` / `From<()>` / `encode()` 编码正确性、`Default` 派生
- `eval(&[..])` / `async_eval(&[..])` 空数组、单元素、多元素

### 4.2 集成测试（新文件 `mlx/tests/p5_7_stream.rs`）

- 默认 stream 路径：现有 `add(&a, &b)?` 行为不变（回归）
- 显式 stream：`add_on(&a, &b, stream)?` 走指定 stream
- 显式 device：`add_on(&a, &b, Device::cpu())?` 走 CPU device 默认 stream
- `()` 等同 default：`add_on(&a, &b, ())?` 与 `add(&a, &b)?` 结果一致
- `Array::try_add_on` 与 free `add_on` 等价
- random builder：`uniform().stream(s).sample()?` 派发到指定 stream
- 批量 eval：`eval(&[&a, &b, &c])?` 一次完成
- `compile::clear_cache()` 不 panic

### 4.3 回归保证

P0–P6.5 现有 ~280 个测试全部不动 —— 默认变体签名不变，调用站点零改动。新增 ~15-20 个 stream-specific 测试。

8 个任务，按依赖顺序：

| # | 任务 | 主要文件 | 依赖 |

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| ~100 个 op 的 shim signature sweep 工作量大 | macro 派生（任务 4）+ 模块化 sweep（任务 5–7 拆分） |
| 中间状态测试不一致（部分 op 改完，部分没改） | 每个 sweep 任务结束都跑全量回归；保持单一 commit 原子 |
| `paste` crate 依赖引入（macro 拼接 ident） | 已是 P5.5+ 标准依赖；可接受 |
| `Stream::index` 非法值传给 FFI | `Stream` 已是 `#[non_exhaustive]` 受控构造；`encode()` 单元测试覆盖 |
| compile 闭包内 stream context 误用 | 文档明示"compile 闭包内 op 继承调用时的默认 stream，不可在闭包内换 stream" |
| 批量 eval 跨 dtype/device 混用 | MLX C++ 自身处理 device 路由；Rust 层不做额外检查 |
