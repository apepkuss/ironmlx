# IronMLX 0.4.0

[简体中文](../zh-CN/release-notes/0.4.0.md)

## Changes since 0.3.0

This release adds a built-in menu bar chat, first-run model setup, Hugging Face
mirror downloads and cancellable model loading. It also expands JSON Schema
support for agent tools. Publication status and downloads are listed on
[GitHub Releases](https://github.com/apepkuss/ironmlx/releases); preparation
evidence is recorded in the [validation record](0.4.0-validation.md).

<!-- release-summary:stable -->
#### New features

- Add a menu bar chat with streamed responses, local conversation history, supported-model image input and thinking controls.
- Guide first-run users through a recommended model download and loading, with background progress and model-ready notifications.
- Add an opt-in hf-mirror.com download source, preserving the selected source for queued, paused and restored tasks.
- Show model-load stages and weight bytes in the Dashboard, allow cancellation, and retain progress across navigation and window reopening.
- Expand JSON Schema validation and constrained tool arguments, including complex schemas used by OpenCode and AFT.

#### Fixes

- Keep more Chat history by capping the per-reply output budget at half the context window, and retry once with the server's remaining allowance when token estimates still overflow.
- Ignore unsupported text API request fields for client compatibility while retaining validation of supported fields.
- Classify model-load failures and keep readiness checks unavailable until DFlash2 startup loading is complete.
- Refresh the no-model window immediately when the App language changes.
- Avoid repeated registration of unchanged local models and clarify the effective scheduler profile without notices for ordinary default or dedicated profiles.

## Menu bar chat and first-run setup

Choose **Chat** from the IronMLX menu bar icon to talk to a local model. Chat
uses the local Responses service and starts it when needed. The window supports
streamed text, Markdown, code, math and the latest 20 locally saved conversations.
Compatible models expose image attachments and thinking controls. Messages are
limited to 100,000 characters; image-capable models accept up to four images per
message, each smaller than 20 MB.

When no chat model is available, the App offers a model appropriate for the
Mac's memory when the supported catalogue contains one. The starter flow tries
huggingface.co first and hf-mirror.com if the first source cannot be reached.
Downloads can continue in the background; the App requests notification
permission to announce readiness. Users can instead open the Dashboard to choose
a model. Chat uses an active DFlash2 model but does not switch DFlash2 models;
that remains a Dashboard operation. See the [user guide](../user-guide.md).

Chat limits each reply to at most half of the context window, including when a
larger output budget is configured. For example, a 4096-token context permits
at most 2048 output tokens, leaving more room for conversation history. Thinking
and the visible answer share that budget. If the latest input alone occupies
more than half the window, the output budget is reduced further; older whole
exchanges are still trimmed when needed. This applies to the built-in Chat;
it does not change backend/API token limits or saved model settings.

When only the latest question remains and the server reports that the input and
output budget exceed the context window, Chat can retry once with the server's
remaining output allowance. This accounts for tokenizer/template overhead that
the initial estimate misses. It does not change saved model settings; inputs
that leave no output room still report the context limit.

## Mirror downloads

The HuggingFace tab adds **Use hf-mirror for downloads**, off by default. New
searches and downloads use the selected endpoint; queued, paused and restored
tasks retain their recorded source. Ordinary Dashboard downloads do not
automatically switch endpoints on failure. Sending an HF Token to the third-party
mirror requires confirmation. This differs from the first-run starter flow's
explicit source fallback. See [model downloads](../user-guide.md) and
[privacy](../privacy.md).

## Model loading, cancellation and readiness

The Dashboard shows loading stages, weight bytes, elapsed time and estimates,
with a sidebar indicator when the panel is closed. Progress survives page
changes and Dashboard reopening. Cancelling a reload retains the loaded
version; cancelling a DFlash2 transition restores the previous configuration.
Cancelling startup DFlash2 restoration restarts the backend in plain mode
without loading a model, retaining its DFlash2 settings for a later load.

The App management API adds load listing and cancellation, and asynchronous
loads return a `load_id`. Inference failures caused by model loading distinguish
invalid configuration (400), cancellation (409) and resource limits (503).
Failed models are not silently retried and their errors omit `Retry-After`.
`/healthz` returns 503 while startup DFlash2 loading is incomplete. These changes
retain existing memory protections. See the [service API](../service-api.md).

Model registration reuses unchanged inputs and scans only the models required
by a load or rescan. Scheduler status and model settings show the effective
profile; ordinary default and dedicated profiles no longer produce notices.
No general performance improvement is claimed.

## Agent schema and request compatibility

The backend expands Draft 2020-12 schema validation and constrained generation
for complex tool arguments. The API profile and documented optional semantics
remain explicit; this is not a claim that arbitrary schemas or every client
workflow have been qualified. Unsupported request fields in text APIs are
ignored while supported parameters retain their validation.

Recorded development checks include the official SDK contract, pinned schema
conformance tests and actual OpenCode/AFT calls with one cached Qwen3.8 27B
4-bit model. They do not establish broad model or performance acceptance. See
the [text and vision API](../text-vision-api.md) and [OpenCode guide](../opencode.md).

## Compatibility and validation

Requires Apple Silicon and macOS 26.4 or newer. Models are downloaded separately
and retain their upstream licenses. See [supported models](../supported-models.md),
[known limitations](../known-issues.md) and the
[candidate validation record](0.4.0-validation.md).

The App product version is `0.4.0`, build `11`. Source preparation, final
tag identity and public release are separate steps. No tag, GitHub Release or
production feed is created by this preparation.
