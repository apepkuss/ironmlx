# IronMLX 0.5.0

[简体中文](../zh-CN/release-notes/0.5.0.md)

## Changes since 0.4.0

This release improves prefix-cache reuse and memory management, and fixes
image-prefill and Gemma4 attention behavior. This document describes the
prepared release; publication status and downloads are listed on
[GitHub Releases](https://github.com/apepkuss/ironmlx/releases).

<!-- release-summary:stable -->
#### New features

- Add a disk-backed DFlash2 prefix cache so eligible prefixes can be reused after restarting the service.
- Allow an in-memory prefix cache without an SSD directory, and reclaim cached prefixes to make room for inference requests.
- Keep eligible model weights GPU-resident by default with an automatic size limit and an explicit CLI override.

#### Fixes

- Bound DFlash2 prefix-cache memory and shrink it under memory pressure or when a request needs more room.
- Prevent the first long image prompt from hanging during chunked prefill.
- Keep Gemma4 sliding-window attention within its window when using paged KV caches, and apply bidirectional attention within each image block.
- Update quinn-udp to 0.5.16 to address RUSTSEC-2026-0538.
<!-- /release-summary -->

## Prefix caching

The CLI option `--prefix-lru-cache-max-bytes` can enable prefix reuse entirely
in memory. The in-memory LRU cache remains disabled unless this budget is configured.
Add `--paged-prefix-cache-dir` to retain eligible prefixes on disk as well.
Ordinary and MTP serving use paged K/V for this cache; DFlash2 retains dense
K/V and its existing decode kernels.

For DFlash2, a disk directory requires an explicit in-memory cache budget.
`--ssd-prefix-cache-max-gb` limits the DFlash2 store within that directory.
Only compatible entries are restored; invalid or incompatible entries do not
qualify as cache hits. Prefixes are saved at reusable chat-turn boundaries.
The cache can release entries under memory pressure and before admitting a
request. Cache eviction can require prefill to run again on a later request.

These changes do not add DFlash2 support for MTP, Prompt Lookup, KV
quantization or Active KV offload. CLI cache controls do not imply a new
Dashboard control. See [DFlash2 configuration](../dflash2-server-api.md).

## GPU-resident weights

`--resident-weights auto` is the CLI default. Eligible loads keep weight buffers
GPU-resident when the total resident allocation fits within two thirds of the
device's recommended working set. `on` requests residency regardless of size;
`off` disables it. The App also enables automatic residency for its backend.

Resident allocations cannot be compressed or swapped, leaving less memory for
other work. Automatic eligibility depends on the loaded model and device.
DFlash2 uses its wired-memory path rather than per-buffer residency. This
release does not claim a general throughput improvement or support for models
larger than available memory.

## Image prefill and Gemma4 attention

Long image prompts can complete their first chunked-prefill request without
the previous scheduling hang. Gemma4 paged KV attention now respects the
sliding-window limit, while tokens belonging to the same image block can
attend bidirectionally. These fixes do not expand the supported model catalogue.

## Compatibility and preparation status

Requires Apple Silicon and macOS 26.4 or newer. Models are downloaded separately
and retain their upstream licenses. See [supported models](../supported-models.md)
and [known limitations](../known-issues.md).

The prepared App product version is `0.5.0`, build `12`. Candidate checks are
recorded separately from this user-facing change summary. Final clean-source
and tag identity, signing, notarization and publication are separate gates;
this preparation creates no tag, public Release or production update feed.
