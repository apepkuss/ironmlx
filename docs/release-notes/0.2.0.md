# IronMLX 0.2.0 release notes

IronMLX 0.2.0 expands the local Apple Silicon runtime beyond text and vision generation with local model import, speech synthesis, text/image/audio embeddings, typed decision-model serving, additional client integrations, and a modular runtime architecture. Release-candidate tags such as `v0.2.0-rc.1` are prereleases for validation and feedback; they are not promoted through the stable update channel.

## 0.2.0 changes since 0.1.0

This overview summarizes the 0.2.0 release line. The candidate sections below record when each change was introduced.

<!-- release-summary:stable -->
- **Local model import:** copy and verify existing model directories into the managed library from the Dashboard, preserving the originals.
- **Speech synthesis:** adds IndexTTS 2.5, WAV and streaming PCM output, and managed reference-voice profiles.
- **Image generation and embeddings:** adds Qwen Image 2.1 text-to-image and single-image editing, plus EmbeddingGemma 2 text, image and audio embeddings. Model-specific licenses and input limits apply.
- **Decision APIs:** adds local Laya serving through System One and the OpenAI SDK-compatible Decisions API, with lifecycle controls and runtime metrics.
- **DeepSeek Harness integration:** adds CLI and Desktop setup guidance for connecting to the local Responses API.
- **DFlash2 improvements:** adds the Qwen3.6 MoE path, compatible image requests and chat-prefix reuse, and improves Qwen3.8 and Qwen3.6 prefill, verification and concurrent execution. The M5 profile has model-specific behavior and Neural Engine controls; measured results apply only to the documented configurations.
- **Model downloads:** adds a supported-model catalogue with quantization variants, validation hints and download pause/resume controls.
<!-- /release-summary -->

## RC4 changes since RC3

The planned RC4 tag is `v0.2.0-rc.4`; the product version remains `0.2.0` and App build increases from RC3's `7` to `8`. This section records source changes. Final build identity, signing, notarization, installation and upgrade acceptance must be verified separately against the final candidate artifact.

See the [RC4 source preparation and regression record](0.2.0-rc.4-validation.md) for the scoped local checks and remaining release gates.

<!-- release-summary:rc.4 -->
- **Qwen3.6 MoE prefill:** improves long-context prefill through tiled matrix multiplication and expert-kernel changes. Eligible single-chunk prompts use one prefill graph, reducing short-prompt startup work under the M5 profile.
- **Single-request DFlash2 verification:** the Qwen3.6 MoE M5 profile verifies the confident leading portion of a greedy draft instead of always using the window-cost budget policy. This reduces verification work without changing the target's acceptance checks.
- **Constrained concurrent requests:** greedy Qwen3.6 MoE requests with decoding constraints, including native reasoning budgets, can now participate in ragged linear batches. Each row applies and advances its own constraint; sampled requests retain their separate path.
- **GatedDelta state fix:** preserves the final state of a single-request linear verification window when its draft is fully accepted, so the next window continues from the committed state.
- **Updated performance comparisons:** refreshes the Qwen3.6 MoE [B1 short](../benchmarks/qwen36-moe-b1-short.md), [B4 short](../benchmarks/qwen36-moe-b4-short.md), [B1 30K](../benchmarks/qwen36-moe-b1-30k.md) and [B4 30K](../benchmarks/qwen36-moe-b4-30k.md) results. The pages identify the measured source, models, hardware and workload; these are not general performance guarantees.

## RC3 changes since RC2

The RC3 candidate uses tag `v0.2.0-rc.3`, product version `0.2.0` and App build `7`, increased from RC2's build `6`. This section records source changes, not completed release acceptance; signing, notarization, Gatekeeper, installation, RC2 upgrade, model recovery and data-preservation results must be recorded against the final candidate artifact.

<!-- release-summary:rc.3 -->
- **OpenAI Decisions API:** adds `POST /v1/decisions` for `aac6fef/laya-multilingual-mlx`, including predicate, typed choice and score answers through the official OpenAI SDK. The App, CLI multi-model service and standalone decision service share Laya execution, lifecycle and metrics with the existing System One endpoint. Inputs remain text-only; this does not provide OpenAI's hosted models. See the [Decisions API](../openai-decisions-api.md).
- **DFlash2 images and chat prefixes:** compatible targets now load their vision encoder on the first image request and serve image-conditioned requests through speculative decoding. The DFlash2 actor reuses eligible text and image prefixes across chat turns with its own in-memory cache. Video, paged/persistent prefix caching, MTP and Prompt Lookup remain unsupported in this path. The App can also pin a DFlash2-loaded target and retain that setting when returning to ordinary serving. See [DFlash2 configuration and usage](../dflash2-server-api.md).
- **Qwen3.8 dense DFlash2:** improves long-context prefill, batched verification and admission of long prompts. The M5 profile can split eligible prefill MLP work between the GPU and Neural Engine. Published [B1](../benchmarks/qwen38-dense-b1-30k.md) and [B4](../benchmarks/qwen38-dense-b4-30k.md) long-prompt comparisons describe the measured hardware, checkpoints and workloads; they are not performance guarantees for other configurations.
- **Qwen3.6 35B A3B DFlash2:** improves expert projections, long-context attention, drafting, verification and adaptive draft budgets. With the M5 profile active, eligible concurrent greedy, unconstrained requests use ragged linear batching with up to four rows; sampled and constrained requests still run alone. The MoE path keeps its own profile and does not use Qwen3.8 tensor groups or the Neural Engine. M5 kernels and batching can change output relative to ordinary decoding, including dependence on the requests batched together. See the [MoE limits](../dflash2-server-api.md#qwen36-35b-a3b-moe) and the measured [B1](../benchmarks/qwen36-moe-b1-30k.md) / [B4](../benchmarks/qwen36-moe-b4-30k.md) long-prompt comparisons.
- **Neural Engine controls:** adds `ironmlx serve --ane auto|off` and a Dashboard switch. `auto` is the default and applies only to eligible Qwen3.8 prefill chunks with the M5 profile active; short prompts, decoding and MoE targets do not use it. `off` keeps computation on the GPU. Health exposes the effective `ane_status`; see the [configuration guide](../dflash2-server-api.md).
- **Dependencies and release diagnostics:** updates `quinn-proto` to `0.11.19` for RustSec advisories and preserves release-archive failure diagnostics. Bilingual benchmark pages now include short- and 30K-prompt comparisons; unused repository-root benchmark suites and obsolete experimental MoE routes are removed.
<!-- /release-summary -->

## RC2 changes since RC1

The RC2 candidate uses tag `v0.2.0-rc.2`, product version `0.2.0` and App build `6`, increased from RC1's build `5`. This section describes the candidate's source changes; signing, notarization and installation/upgrade acceptance are recorded separately against the final release artifact.

<!-- release-summary:rc.2 -->
- **Qwen Image 2.1:** adds text-to-image generation and single-image conditional editing for `mlx-community/Qwen-Image-2.1-MLX-4bit` through `POST /v1/images/generations` and `POST /v1/images/edits`, including App download and model lifecycle controls. Masked inpainting and image variations remain unsupported. See the [Image generation API](../image-generation-api.md) and the model's Qwen Research License conditions.
- **Supported-model catalogue:** groups downloadable models by type and quantization variant, with repository, size, memory and validation hints. Download pause/resume and update controls are available in the Dashboard. Auxiliary drafts remain separate from ordinary models; downloading a variant does not establish runtime compatibility. See the [user guide](../user-guide.md#download-and-update-models).
- **EmbeddingGemma 2:** adds BF16 and affine4 text, image and audio embeddings, ordered multimodal input and Dashboard metrics. Video embeddings remain unsupported. See the [Embedding API](../text-embeddings.md).
- **Qwen3.8 DFlash2:** adds verification and scheduling improvements, ragged cross-request draft batching, an M5 profile for qualified configurations, and prefix-cache-miss prefill optimizations. KV capacity and output-tail fixes prevent affected requests from ending early; an incomplete Chat Completions stream reports an error instead of successful completion. Tree verification and position-keyed sampling are explicit options; wider verification lanes are subject to checkpoint and runtime capability checks.
- **Qwen3.6 35B A3B DFlash2:** adds the matching MoE target/draft path, adaptive draft-budget handling and row-exact ragged batching for eligible greedy, unconstrained requests. Affine 4/5/6/8-bit targets are supported with a matching draft loaded as 4-bit or BF16; OptiQ targets and 8-bit drafts are rejected. Sampled or constrained requests keep their separate execution paths. Experimental M5 affine4 projections can change output relative to ordinary MLX decoding.
- **DFlash2 download compatibility:** allows download-only auxiliary drafts whose target tap count differs from their own layer count, while preserving their auxiliary role; loading and target/draft pairing retain their compatibility checks. See [Supported models](../supported-models.md) and [DFlash2 configuration and usage](../dflash2-server-api.md). Acceleration remains text-only and cannot run alongside MTP; performance depends on the checkpoint, hardware and workload.
- **Documentation and build reproducibility:** reorganizes the bilingual guides and website, aligns Embedding API terminology, and fetches the pinned MLX verification commits required by clean CI builds.

## System requirements

- Apple Silicon (arm64), macOS 26.4 or later; Intel Macs are not supported.
- Memory needs depend on model size, quantization, context and concurrency. Architecture support does not guarantee that every device can load a checkpoint.
- Model weights and auxiliary resources are downloaded separately and remain subject to their upstream licenses.

## Import models already on this Mac

- Dashboard **Models → Model Manager** can import an existing model directory containing `config.json`, weights and a tokenizer.
- IronMLX copies and verifies the model into its managed library; the original directory remains unchanged.
- Snapshots with a valid IronMLX manifest retain their repository identity. Other local directories are stored under the managed `standalone` namespace.
- The confirmation step shows the source, destination and copy size before import. A complete copy requires sufficient free storage.

See the [user guide](../user-guide.md#import-a-model-already-on-this-mac) for directory selection and model-management details.

## Speech synthesis and voice profiles

- The App supports the verified `mlx-community/IndexTTS-2.5-fp16` profile, including resource preparation, model loading, complete WAV responses and streaming PCM output.
- `POST /v1/audio/speech` accepts Base64 reference audio or a managed voice ID.
- Voice-management endpoints and Dashboard controls create, update, preview, enable and delete local voice profiles.
- Managed reference recordings remain local. They are not uploaded by IronMLX.

See the [speech API](../audio-speech-api.md) for supported formats and limits, and the [user guide](../user-guide.md#speech-synthesis) for App voice configuration and model settings.

## Text, image and audio embeddings

- EmbeddingGemma 2 BF16 and affine4 variants support `POST /v1/embeddings` for text, images, audio and ordered combinations, including multiple media segments.
- Model adapters handle RGB conversion, resizing, image patch preparation and image-token placement; clients send original JPEG/PNG/WebP data URLs. Audio adapters decode WAV/FLAC/MP3, downmix and resample to 16 kHz, then prepare model-specific log-mel features and audio tokens.
- Outputs support 128, 256, 512 and 768 dimensions with float or base64 encoding.
- Dashboard status shows embedding queue activity, completed/failed requests, P50 latency, input-token throughput and vector throughput.
- Embedding models share loading, unloading, pinning, TTL and memory protection. Video embeddings remain unsupported.

See the [Embedding API](../text-embeddings.md) for exact input limits and the BF16/affine4 qualification scope.

## Decision-model serving

- The App can download, load, unload and restore the typed `aac6fef/laya-multilingual-mlx` decision model.
- `POST /v1/systemone` provides the phase-one TypeSafe-compatible System One contract.
- `POST /v1/decisions` provides the OpenAI SDK-compatible predicate, typed choice and score contract using the same local Laya runtime.
- Dashboard status includes decision-runtime request counts and recent latency, token-rate and question-rate metrics.
- The standalone CLI exposes the same typed execution path for development and validation.

See the [Laya and System One guide](../laya-systemone-api.md) and [Decisions API](../openai-decisions-api.md) for the request contracts, runtime settings and client examples.

## API and client compatibility

- Existing OpenAI Chat Completions, Responses and Anthropic Messages routes remain available for compatible text and vision models.
- Model discovery can report effective context and output-token capacities when they are reliably known.
- Reasoning output reserves answer space for supported native templates and preserves completed/incomplete item state for replay.
- DeepSeek Harness CLI and Desktop setup guidance joins the existing Hermes Agent and oh-my-pi integrations.

## Runtime and release engineering

- Shared tensor, weight, cache and sampler code is separated into `ironmlx-core` and `ironmlx-lm`; image generation lives in `ironmlx-image`; scheduling and execution live in `ironmlx-runtime`; speech and decision paths use `ironmlx-audio` and `ironmlx-decision`.
- CI range resolution, distribution materials, signed update feeds and release workflows include additional reproducibility and failure-boundary checks.
- RC sequence numbers and App build numbers are independent. `CFBundleVersion` increases globally so Sparkle can compare updates across release lines.

## Compatibility and known limitations

- Speech synthesis is limited to the documented IndexTTS 2.5 profile and output formats; model metadata alone does not imply runtime support.
- Decision serving is limited to the documented Laya model and System One / Decisions contracts; Decisions inputs are text-only.
- DeepSeek Harness compatibility is bound to the revisions and request paths documented in the [integration guide](../dsh.md).
- DiffusionGemma, MTP, DFlash2 and multimodal support retain their model-specific constraints. Review [Supported models](../supported-models.md) and [Known issues](../known-issues.md) before deployment.
- RC and stable update channels are separate. Installing or switching channels is an explicit user action.
