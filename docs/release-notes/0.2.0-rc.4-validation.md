## Evidence and reproduction

Local evidence is retained under `.build/release-readiness/rc4/`:
`evidence.json` records SHA-256 values for the observed model files, MLX
archives/metallib and test executables; the directory also contains build,
Clippy and real-model test logs. These local artifacts are intentionally not
distributed with the App or committed as model data.

The first real-model attempt failed during weight evaluation with an MLX
`vector` runtime error before any generation. Making the pinned
`mlx.metallib` discoverable beside the test executables resolved the failure,
without changing source code. The original failure is retained as
`real-model-tests-attempt1.log`; successful logs are `confidence-verify.log`
and `ragged-constrained-rows.log`.

To reproduce from the repository root with the same existing cache:

```bash
set -e
export MLX_DIR="$PWD/.build/app-bundle/mlx-install"
export MLX_METAL_PATH="$MLX_DIR/lib"
export CARGO_NET_OFFLINE=true
export QWEN36_MOE_MODEL="$HOME/.ironmlx/models/huggingface/mlx-community--Qwen3.6-35B-A3B-4bit/snapshots/38740b847e4cb78f352aba30aa41c76e08e6eb46"
export DFLASH2_MOE_MODEL="$HOME/.ironmlx/models/huggingface/incoai--Qwen3.6-35B-A3B-DFlash2/snapshots/51ef7b6923ad6c14cb1bb41c37a9041446496ab6"
cargo test --locked --release -p ironmlx-runtime \
  --test dflash2_confidence_verify --test dflash2_ragged_constrained_rows --no-run
test ! -e target/release/deps/mlx.metallib
test ! -L target/release/deps/mlx.metallib
ln -s "$MLX_DIR/lib/mlx.metallib" target/release/deps/mlx.metallib
trap 'rm -f target/release/deps/mlx.metallib' EXIT
cargo test --locked --release -p ironmlx-runtime \
  --test dflash2_confidence_verify --test dflash2_ragged_constrained_rows \
  -- --ignored --nocapture --test-threads=1
```

## Remaining release steps

The final preparation commit must pass remote CI after it is pushed to `dev`.
This record does not assert that CI has run against uncommitted changes.
After that gate, `main` can be fast-forwarded and the immutable
`v0.2.0-rc.4` tag created under the release process.

Tag/Bundle identity, final archive checks, signing, notarization, Gatekeeper,
installation, RC3 upgrade, model recovery and data preservation must still be
verified against the final candidate artifacts. Neither the existing local
App nor these source tests constitutes that final artifact acceptance.
