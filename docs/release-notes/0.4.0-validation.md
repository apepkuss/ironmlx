## Release body and user-visible behavior

The stable summaries now contain **New features** followed by **Fixes**, and
**新增功能** followed by **问题修复** in Simplified Chinese. The existing renderer
includes these sections in the GitHub Release body; download links, release
status and compatibility remain owned by the shared template. Other release
versions and the template are unchanged. `RELEASE-NOTES.md` and its HTML preview
are local previews only; no GitHub Release body is edited or published.

For built-in Chat, the desired output is the smaller of the configured/default
budget and half the known context window. A 4096-token window therefore permits
at most 2048 output tokens, including when 4096 is configured. Reasoning and the
visible answer share this budget. If the latest input alone exceeds half the
window, the remaining estimate can reduce output further; old exchanges are
still trimmed when necessary. Backend/API token limits and saved model settings
are unchanged. Tokenizer/template mismatch can still trigger one bounded retry
using the server's positive, smaller remaining output allowance.

The controller's new long-prompt fixtures use a fake transport to exercise that
retry after the half-context cap. Their token counts are synthetic; they are not
real-tokenizer or live-model evidence. Live checks must record their own input,
response and history scope separately, including whether the server context
limit was discovered by an initial 413 response.
