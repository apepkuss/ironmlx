## Chat follow-up and source freeze

Native follow-up found a real short-message failure with a 4096-token runtime
context and Chat's default 4096-token output budget (the model's explicit output
setting was empty). The input estimate omitted template/tokenizer overhead: the
server reported 22 input tokens and a remaining output allowance of 4074. The
App reported context overflow rather than using that allowance. The failed
native attempt and direct HTTP reproduction are retained under the initial
directory's `native-chat-followup/`; they are excluded from passing acceptance.

Chat now retries once with the server's positive, smaller output allowance when
no earlier exchange remains to trim. HTTP and pre-token streaming failures use
the same rule; zero, negative or non-reducing limits are not retried, and a
second overflow still fails. The last question and saved model settings remain
unchanged. This is a Swift-only fix; backend context limits are unchanged.

The controller suite initially passed 42 tests. Final review also counts only
messages actually sent when deciding whether history remains to trim, so earlier
unanswered questions cannot prevent budget recovery. The full Swift Release
suite, including that regression, passed 811 tests. Source fingerprints, build logs and native results are under
`.build/release-readiness/0.4.0-chat-context/`. Native testing used a precommit
App with the rebuilt Swift executable and unchanged pinned Rust/MLX components;
this derivative's new App signature was verified, but it was not notarized.

The maintainer opened Chat from the real menu bar and later closed/reopened it
when CUA lost its window target. Native AX controls then verified:

- The previously failing short prompt returned `IRONMLX_CHAT_OK` with the same 4096-token runtime context.
- The answer remained visible after closing/reopening Chat. With an explicit 512-token output budget, a follow-up question recalled the same marker.
- New Chat started empty and History restored both completed exchanges.
- A length-limited reply was retained with a truncation notice; a separate immediate Stop retained a nonempty partial reply marked `stopped`.

Four user prompts produced three persisted conversations. Internal warmups and
413 retries are separate from that prompt count. The initial failed Stop attempt
reached the length limit before cancellation and is counted only as truncation
coverage. Temporary Apps/model clones were removed and production preference
changes were restored byte-for-byte.

After the authorized source commits, the clean rebuild, signing/notarization,
archive, installation and full-App update results are recorded in the follow-up
`readiness.json`, with the exact commit and artifact hashes. This tracked record
preserves the earlier working-tree and precommit identities; it does not relabel
those artifacts as clean-source builds.
