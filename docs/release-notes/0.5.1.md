# IronMLX 0.5.1

[简体中文](../zh-CN/release-notes/0.5.1.md)

## Changes since 0.5.0

This patch improves cache reuse and memory use, and fixes Gemma4 batching and
prefill error handling. Publication status and downloads are listed on
[GitHub Releases](https://github.com/apepkuss/ironmlx/releases).

<!-- release-summary:stable -->
#### Fixes

- Reuse Gemma4 prefixes for chunked text and batched image prompts, and batch cold text prefill for models without position IDs.
- Preserve batched projections during Gemma4 K3V4 sequential verification.
- When a prefill batch does not fit, process its rows separately and refuse only requests that still do not fit.

#### Performance and memory

- Grow dense KV caches as requests need them, and account for memory as caches grow.
- Share prefix-cache KV segments between related entries, write only new segments to SSD, and restore segments without first joining them into a dense copy.
- Use split-K paged decode attention and let Gemma4 shared-KV layers read paged decode views directly.
- Keep DFlash2 weights GPU-resident through buffer pinning, including weight layouts created during warmup.
<!-- /release-summary -->

## Compatibility and validation

Requires Apple Silicon and macOS 26.4 or newer. The prepared product version is
`0.5.1`, build `13`. This release does not expand the supported model catalogue.
Cache reuse depends on matching model and execution settings; a cache miss can
require prefill to run again. Memory accounting does not guarantee that every
request fits available memory.

The changes above describe implementation behavior, not a general throughput or
memory-reduction measurement. Candidate validation and its limits are recorded
separately. Final tag identity and public distribution require maintainer
approval. See [supported models](../supported-models.md),
[known limitations](../known-issues.md), and [release process](../versioning-and-releases.md).
