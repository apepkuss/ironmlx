# IronMLX 0.1.0 release notes

Status: first release candidate in preparation; not publicly released. RC builds are for testing and feedback.
IronMLX is a local inference App for Apple Silicon with a Dashboard and HTTP APIs for compatible clients.

## System requirements

- Apple Silicon (arm64), macOS 26.4 or later; Intel Macs are not supported.
- Memory needs depend on model size, quantization, context and concurrency. Architecture support does not guarantee that every device can load a checkpoint.
- The self-contained App bundles its Rust/MLX runtime; no separate Python inference environment is required.

## Supported model architectures

| Model family | Configuration model_type | Inputs |
| --- | --- | --- |
| Qwen 3.5 Dense; Qwen 3.6 / 3.8 Dense using the same architecture | `qwen3_5` | Text; images with compatible vision configuration and weights |
| Qwen 3.5 / 3.6 MoE | `qwen3_5_moe` | Text; images with compatible vision configuration and weights |
| Gemma 4 / Gemma 4 Unified | `gemma4`, `gemma4_unified` | Text; images with compatible vision configuration and weights |
| GLM-4 MoE Lite | `glm4_moe_lite` | Text |
| Llama GQA Dense, including compatible MiniCPM5-1B | `llama` | Text |
| MiniCPM-V 4.6 | `minicpmv4_6` | Text and images; image input requires compatible vision weights |
| DiffusionGemma | `diffusion_gemma` | Text and images through a separate block-diffusion generation path |

These are loader capabilities, not an acceptance list for every named checkpoint. Configuration, tokenizer,
chat template, weight layout and quantization metadata must match. The [supported model matrix](../supported-models.md)
records validated checkpoints and per-model reasoning, tool and cache boundaries.
Weight formats include Affine 2/4/5/6/8-bit, OptiQ mixed-bit and MXFP4/MXFP8, subject to the matrix's parameters.

## APIs and Agent integration

- OpenAI Chat Completions, stateless Responses and Anthropic Messages compatible APIs, with HTTP/SSE streaming.
- Native reasoning, structured function calls and history replay where supported by the model/template. Clients execute tools.
- Structured Outputs and JSON Schema constraints within the [API compatibility matrix](../api-compatibility-matrix.md).
- Hermes Agent and oh-my-pi Provider setup guides with official documentation links and compact sticky headers.

## Model management and inference optimization

- Unified Dashboard download queue for Hugging Face / ModelScope, resumable downloads, cancellation,
  preflight checks, immutable snapshots and integrity verification.
- Load/unload, default and pinned models, TTL management and persistent settings.
- Continuous batching, paged KV and prefix caches, Prompt Lookup and memory protection, subject to runtime/model compatibility.
- MTP or auxiliary drafters for compatible Qwen/Gemma models; a separate Qwen3.8 DFlash2 text path.
  DFlash2 does not combine with MTP, Prompt Lookup, KV quantization, paged/SSD prefix caches or active KV offload.
- Dashboard runtime status, logs, dynamic log-level changes and local redacted diagnostic exports.

## Installation, updates and privacy

Public RC artifacts use Developer ID signing, Apple notarization and stapled tickets. RC updates use a channel
separate from stable updates. Third-party licenses, Notices and SBOM accompany the App; model weights do not.
Loopback is the default. Optional LAN mode uses HTTPS, API keys and Keychain credential storage.
Diagnostic exports are generated locally, exclude prompts/credentials and are not automatically uploaded.

## Known limitations

- Image input accepts JPEG/PNG/WebP base64, not remote image URLs. Video or audio generation is not promised.
- Listing embedding, reranker, ASR or TTS metadata does not mean the generation backend can load those models.
- DiffusionGemma has no KV cache, Prompt Lookup or MTP; its separate path supports a smaller sampling-parameter set.
- Fresh-system installation remains untested. Public-version upgrade validation is deferred to a later release because this is the first release.
- Model support does not grant commercial-use or redistribution rights; upstream terms apply.

Acceptance evidence and exclusions are recorded in the [RC acceptance record](../zh-CN/release-acceptance/0.1.0-rc.1.md).
