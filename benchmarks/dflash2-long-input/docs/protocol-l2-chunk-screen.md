# L2 诊断协议：prefill 分块大小筛查

2026-10-07 写定，在运行之前。这是诊断筛查，不是验收，不修改代码或生产默认配置。

## 固定项

**基线：**
- 逐项基线：提交 8e6d01bc，冻结二进制 `reports/dflash2-long-input/binaries/ironmlx-long-baseline-8d3a42dc`（sha256 8d3a42dc8ee05cc805791a0f6acaf907f48a71bc5500f92b46630fa9a726cc65）。
- 整轮初始基线：9f9c6580 / 4fc49e92，本筛查不使用。

**服务配置（三种配置只有分块大小不同）：**
- 产品默认（M5 profile 自动启用）；
- `--max-sequences 1`、`--max-cache-cap 40960`；
- 不开前缀缓存，App 环境，端口 18490；
- 分块大小用 `--prefill-chunk-size K`，K 取 2048、4096、8192。

**请求（每个会话）：**
1. 一个短预热（max_tokens 64）；
2. 30K code-1（max_tokens 1024）；
3. 30K knowledge-1（max_tokens 1024）。

请求间隔 5 s，会话间隔 10 s，每个会话都是新进程。

## 三类运行（相互分开）

1. **性能测量（`results/l2-perf-v1`）：**
   - 不开任何诊断，6 轮 × 3 种配置，共 18 个会话；
   - 每轮的配置顺序按拉丁方安排：
     - R0：2048、4096、8192
     - R1：4096、8192、2048
     - R2：8192、2048、4096
     - R3：2048、8192、4096
     - R4：4096、2048、8192
     - R5：8192、4096、2048
   - 只运行一次，不提前停止，不重试；
   - 无效会话（服务失败、响应无效、内存不足）保留记录并报告，继续执行下一个计划会话。
2. **正确性（`results/l2-correctness-v1`）：**
   - 每种配置 1 个会话，开 token-id 诊断，请求同上；
   - 逐请求比较 4096、8192 与 2048 的 prompt token、生成 token 和结束原因。
3. **路径诊断（`results/l2-path-v1`）：**
   - 每种配置 1 个会话，开 `IRONMLX_DIAGNOSTIC_DFLASH2_PREFILL_PHASES`，记录实际分块和每块耗时，请求同上；
   - 只用来核对路径，不用于判断收益。

## 记录内容

**每个请求：**
- 客户端 TTFT、Decode（completion tokens − 1 再除以流式输出的时间跨度）、E2E；
- 服务端 prefill 时间和生成时间（`/healthz` 差值）；
- 请求窗口内的进程树 footprint 峰值（50 ms 采样）；
- 请求结束后的 MLX active、cache、peak；
- 输出哈希和结束原因。

**每个会话：**
- 进程生命周期的 footprint 峰值；
- 服务日志中的路径标记：
  - `B1 M2048 BF16 affine4 gate-up QMM BM128 active`；
  - `… down QMM BM128 active`；
  - `B1 2048-row BF16 D256 NAX attention active`；
  - `realized-layout native fallback`。

## 分析（固定）

**统计方法：**
- 每种配置、每个任务，取 6 轮的中位数；
- 4096、8192 分别对 2048 计算比值；两个任务的比值取几何平均；
- 95% 区间用配对轮次 bootstrap（10000 次，种子 20261007）；
- 内存取峰值中位数之比，同时报告绝对增量。

**结论规则（筛查用）：**
- **值得实施：** 必须同时满足以下各项：
  - TTFT 比值点估计 ≤ 0.97 且区间上界 < 1.00；
  - E2E 比值点估计 ≤ 0.98 且区间上界 < 1.00；
  - Decode 区间下界 ≥ 0.97；
  - 生命周期峰值内存增量 ≤ 5%；
  - 正确性运行中 token ID 与 2048 一致；若不一致，必须有可解释的原因，并由 Boss 决定能否接受。
- **收益不足：** TTFT 或 E2E 达不到上面的门槛。
- **证据不足：** 某配置的无效会话超过 1 个，或结果与路径诊断互相矛盾。

**解读限制：**
- 4096、8192 会退出 BM128 和 D256 NAX 特化路径，同时减少分块次数，两种效应混在一起，无法单独归因于分块固定开销。
- 只覆盖两个 30K 任务。
- 结论值得实施时，按 `benchmarks/dflash2-b4-throughput/docs/protocol.md` 的方式另行制定正式验收协议。

## 运行前补充（2026-10-07，性能测量开始前写入）

路径诊断（`results/l2-path-v1`）的 4096 会话出现了标记 `[experimental] masked causal softmax fallback active`（见 `mlx-sys/shim/src/prefill_masked_softmax.cc`）。
- 触发原因：查询行数超过 2048 时 D256 NAX 注意力不适用，MLX 对 head_dim 256 走 op 级回退。
- 这条回退会按 [头数, 分块行数, key 长度] 生成完整的分数矩阵，因此内存和耗时都会随分块变大而上升。

处理：
- 把这个标记加入每个会话的路径标记记录；
- 性能测量、正确性运行的样本数、顺序、门槛和统计方法都不变。

另外，路径诊断开始运行后，`run_l2.py` 有两处修改，都在性能测量和正确性运行开始之前完成：
- 正确性会话改为等待 token-id 记录写完；
- 增加上面这个标记。

这两处都不影响路径诊断的测量内容。
