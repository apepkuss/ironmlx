## 有效性与无效运行（预登记）

**会话无效的情形：**
- 服务启动失败或中途退出；
- 任一请求无效：非 200、出错、无 `[DONE]`、无首 token，或结束原因不是 stop/length；
- 审计失败：首请求或零命中请求的命中 token 不为 0，或没有记到一次 miss；任何完全重复（含 R1）没有命中整个 prompt。

**处理规则：**
- 无效会话保留全部记录，不重试、不补齐，继续执行下一个计划会话。
- 一个轮次只有两个会话都有效时才计分。
- 有效轮次少于 20 时，主判据记为“无法判定”，整体验收保持未完成。
- 二进制哈希不一致时立即停止整批运行，结论为“无效运行”。

## 主判据（与原判据相同）

- **统计量：** C/B = C 臂各有效轮次 R1 TTFT 的中位数，除以 B 臂的中位数。
- **满足条件：** 点估计 ≤ 1.10。
- **区间：** 按配对轮次做 bootstrap 95% 区间（重抽轮次，10000 次，种子 20261006），作为报告项。

## 同时报告（不设判据）

- 每轮两臂的原始 R1 TTFT 和服务端 prefill 时间；
- 每轮绝对差 C − B（ms），以及其中位数和 bootstrap 95% 区间；
- 两臂的慢峰比例：沿用“服务端 prefill > 60 ms”的定义，不另选阈值。

## 正确性核对（必需项）

- 每个有效会话的 R1 命中 token 等于 prompt token（30732）；
- R1 输出与同会话 30K 零命中的输出相同；
- 同一臂各会话的 R1 输出相同，且 B 与 C 的 R1 输出相同。

任何一项不满足，都记为正确性未满足；计时结果照常报告。
