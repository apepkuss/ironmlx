# ragged 草稿预算候选：重审结果

2026-10-08。协议：`docs/protocol.md`（正式运行登记的 sha256 0b86196b…）。正式运行 `formal-v1` 只执行了一次。

## 结论：放弃该候选

B4 收益不足，吞吐和整批完成时间两项门槛都没有达到。按协议放弃，不继续扫描其他预算值。各项非退化门槛和正确性都满足。

旧候选 2b 的失败记录（B4 +3.2%，B1 短输入 TTFT 1.205）保持不变。本轮结果不推翻它，也不能用来解释它。

**结果口径：** 本轮是统一初态后，包含升压与受限阶段的混合状态结果。两臂每个会话都从相同的可观测起始条件开始，会话运行中升压、进入受限状态的过程都计入成绩。它不是只在受限状态或只在空闲状态下的收益。

## 1. 正确性（正式测量之前）

**ragged 原型对比**（`proto-check-v3.json`，另有 `proto-check-v2.json`）：
- 普通批（414 个批窗口，宽度 2、3、4 都出现，重组 3 次）和成员变化（延迟加入，第 2 行在第 40 个批窗口后取消；207 个批窗口，重组 5 次）两次运行中：
  - 每行的 token 序列和结束原因都与单请求基线完全一致；
  - 被取消的行与基线的对应前缀一致；
  - 其他行结束后，剩余行回到单行窗口继续生成（最多 307 个窗口），输出仍然一致。
- ragged 窗口中逐行最多产出 4 个、接受 3 个，预算 3 生效。
- 单请求基线每个窗口的草稿数为 7（被长度上限截短的最后一个窗口除外），单行预算没变。
- 执行记录：v1 和 v2 中有三次运行因原型工具的限制失败（缺 M5 profile 设置；没有筛掉接近长度上限的行），与候选无关，记录保留，见协议第 9 节。

**服务端 token ID 对比**（`results/correctness-v1`）：
- 21/21 完全一致，包括 token ID、取消和失败状态。
- 草稿数 35997 → 25257，接受率 0.317 → 0.415。

## 3. 设备状态（辅助说明，不改变判定）

**数据来源：** 压力是 libnotify `com.apple.system.thermalpressurelevel` 的原始值；GPU 功率是 IOReport Energy Model "GPU Energy" 能量差除以采样间隔，是 SoC 内部估算，不是整机功率。

| | A | B |
| --- | --- | --- |
| 会话开始时芯片最高温度（中位/最大） | 44.73 / 44.93 °C | 44.69 / 44.93 °C |
| 起始条件等待（中位/最大） | 107.9 / 118.0 s | 108.2 / 120.3 s |
| B4 计分批次中出现非 0 压力的批数 | 15/24 | 14/24 |
| B4 批次 P13 驻留比例（中位） | 0.37 | 0.64 |
| B4 批次 GPU 功率估算（中位） | 69.3 W | 63.1 W |
| B4 批次芯片最高温度（中位） | 80.9 °C | 79.8 °C |
| B1 短输入：出现非 0 压力的请求数 | 24/24 | 24/24 |
| B1 短输入 P13 驻留比例（中位） | 0.06 | 0.10 |

- **起始条件一致：** 两臂起始条件相同，所有会话都在 600 s 上限内满足。
- **会话内会进入受限状态：** 大多数 B4 批次（A 15/24，B 14/24）在运行中出现非 0 压力，B1 短输入 24/24 在非 0 压力下进行。所以本轮成绩是统一初态后，包含升压与受限阶段的混合状态结果，样本全部保留。
- **B 臂功率较低、P13 驻留较多：** 与草稿和验证工作量减少一致。这只是观察，不能据此推断 B 的吞吐收益来自哪里，也不能据此推断如果状态受控收益会有多大。
