        Metrics Reference
      

      

        

          

            
TTFT (Time to First Token)

            
Latency before the model starts responding. Measures prompt processing (prefill) speed. Lower is better.

          

          

            
TPOT (Time per Output Token)

            
Average time between each generated token. Measures decode speed. Lower is better.

          

          

            
tg TPS (Token Generation TPS)

            
Output tokens generated per second. Inverse of TPOT. Higher is better.

          

        

        

          

            
pp TPS (Prompt Processing TPS)

            
Input prompt tokens processed per second during prefill. Higher is better.

          

          

            
End-to-End Latency

            
Total time from request submission to complete response. Includes prefill + generation.

          

          

            
Total Throughput

            
Total tokens processed per second (input + output). Measures overall system utilization.

          

          

            
Batch Size

            
Number of concurrent requests processed simultaneously. Larger batches increase throughput but add per-request latency.

          

          

            
Speedup

            
Token generation throughput multiplier relative to single-request baseline (1x). Higher is better.

          

          

            
pp TPS/req (Per-request Prompt TPS)

            
Prompt processing throughput divided by batch size. Shows per-request prefill speed under batch load.

                How hot cache works
                Caches frequently used prefixes in memory to reduce repeated request work. Auto mode estimates a conservative limit from system unified memory, capped at 8GB; manual mode sets the memory cache limit. It follows the Enable Cache switch. Save settings and restart the service to apply changes.

            Cold Cache Limit (SSD Cache)
            
              
              
                How SSD cache works
                Persists Prefix Cache data on local SSD to reduce prefill work for repeated long prefixes. The maximum value is adjusted from available disk space. It follows the Enable Cache switch; turn off Enable Cache to disable it. Save settings and restart the service to apply changes.

SSD Cache Directory

        

      

      

        

          

            Active KV Cache Offload
            
              
              
                Experimental cache residency
                Moves paused active KV cache payloads to local SSD storage so new requests can run when sequence slots are full.
                Enabling it does not mean offload happens immediately. The system triggers it automatically when scheduling, KV residency pressure, or request park/restore requires it; it may stay idle when the system is idle or memory pressure is low.
                Applicable: Full Attention dense/paged, TurboQuant packed Full Attention, and MLA.
                Not applicable: GatedDelta/Linear and MTP speculative side cache.
              
            
          

          
Experimental. Keep a hot KV window resident and move paused active KV cache payloads to SSD for long logical MAX CONTEXT TOKENS.

Use TurboQuant to reduce runtime KV Cache memory usage for long contexts. K3V3 saves more memory, K4V4 is more conservative, and K3V4 is the recommended balanced option.

Communication Backend
Transport used for inter-node communication. Auto picks jaccl when Thunderbolt Bridge is available, otherwise ring (TCP).

        

          
        

      

      

        
Parallel Mode
How the model is sharded across nodes. Auto picks TP / PP / Hybrid based on topology and head divisibility.

        

          
        

      

      

        
      

    


    
    

      

        
        Requirements
      

      

        

          ①
          All nodes must be Apple Silicon Macs (M1 or later). x86 machines are not supported.
        

        

          ②
          All nodes must load the same model (same HuggingFace repo or local path).
        

        

          ③
          Nodes must be on the same network. Ensure firewall allows ports 9068, 19100, 19101.
        

        

          ④
          Tensor Parallel requires n_kv_heads divisible by node count. Otherwise Pipeline Parallel is used automatically.
        

        

          ⑤
          For best performance, connect nodes via Thunderbolt cable and enable "Thunderbolt Bridge" in macOS System Settings → Network.

                MTP uses companion prediction weights to propose multiple candidate tokens, which the main model then verifies. Accepted candidates can reduce generation steps and improve speed; actual gains depend on the model, sampling settings, and request content.

                Draft Tokens sets the maximum number of candidates proposed in each round; Auto uses the automatic strategy.

Keeps matching history from completed requests so later similar requests can also benefit from repeated-text acceleration.
